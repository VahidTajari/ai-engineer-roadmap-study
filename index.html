روز ۱ — مقدمه: AI Engineer دقیقاً چه کاری انجام می‌دهد؟

این بخش مطابق شاخه‌ی Introduction در رودمپ شماست. هدف امروز ساختن نقشه‌ی ذهنی کل مسیر است، نه رفتن عمیق در پیاده‌سازی هر مفهوم.

هدف پایان درس: بتوانی تفاوت AI Engineer و ML Engineer را توضیح بدهی، جایگاه LLM، Inference، Training، Embedding، Vector DB، RAG، Agent و Prompt Engineering را در یک سیستم واقعی تشخیص بدهی.

1) AI Engineer کیست؟

AI Engineer معمولاً مهندسی است که قابلیت‌های مدل‌های هوش مصنوعی—به‌خصوص مدل‌های از پیش‌آموزش‌دیده—را به یک محصول نرم‌افزاری قابل استفاده تبدیل می‌کند. تمرکز اصلی او اغلب روی integration، orchestration، data flow، reliability، evaluation، security و productization است.

مثال
ساخت دستیار پاسخ‌گویی روی اسناد شرکت با یک LLM، Embedding، Vector DB و RAG.
نگاه مهندسی
مدل فقط یک جزء سیستم است؛ API، داده، احراز هویت، observability، هزینه، latency و fallback هم مهم‌اند.

2) AI Engineer در برابر ML Engineer

AI Engineer
بیشتر با مدل‌های آماده کار می‌کند، API/SDK را به محصول متصل می‌کند، RAG/Agent می‌سازد و روی تجربه‌ی محصول و production تمرکز دارد.
ML Engineer
بیشتر با چرخه‌ی مدل، training pipeline، feature/data pipeline، experiment، serving و performance مدل درگیر است.

این دو نقش مرز کاملاً صلب ندارند و در بعضی تیم‌ها هم‌پوشانی زیادی دارند.

3) AI در برابر AGI

AI سامانه‌هایی که وظایف مشخصی مثل تولید متن، تشخیص تصویر، ترجمه یا توصیه‌گری را انجام می‌دهند.
AGI اصطلاحی برای هوش عمومی در سطح گسترده و قابل‌انتقال میان حوزه‌های مختلف؛ در این رودمپ یک مفهوم زمینه‌ای است، نه موضوع اصلی پیاده‌سازی.

4) LLM چیست؟

Large Language Model مدلی است که روی حجم بزرگی از داده‌های متنی آموزش دیده و می‌تواند بر اساس context ورودی، توکن‌های بعدی را مدل‌سازی و تولید کند. در محصول، ما معمولاً با مدل از طریق API یا runtime تعامل می‌کنیم.

5) Training و Inference

Training
مرحله‌ای که پارامترهای مدل با استفاده از داده و فرایند بهینه‌سازی یاد گرفته/تنظیم می‌شوند.
Inference
مرحله‌ی استفاده از مدل آموزش‌دیده برای تولید خروجی روی ورودی جدید.

در مسیر AI Engineer، در بسیاری از پروژه‌ها بخش عمده‌ی کار روزمره روی Inference و استفاده‌ی مهندسی از مدل‌های آماده است.

6) Embedding و Vector Database

Embedding یک نمایش عددیِ برداری از محتواست که شباهت معنایی را قابل محاسبه می‌کند. Vector Database برای ذخیره، index و جست‌وجوی این بردارها بهینه شده است.

زنجیره‌ی ذهنی: متن → Embedding → Vector → ذخیره در Vector DB → Similarity Search

7) RAG چیست؟

Retrieval-Augmented Generation یعنی قبل از تولید پاسخ، اطلاعات مرتبط از یک منبع بیرونی بازیابی شود و همراه سؤال به مدل داده شود. هدف، متصل‌کردن مدل به دانش اختصاصی یا به‌روزِ سیستم است.

Pipeline ساده: سؤال کاربر → Embedding سؤال → Retrieval → Context → LLM → پاسخ

8) AI Agent چیست؟

Agent سیستمی است که مدل را فقط برای «پاسخ متن» به‌کار نمی‌گیرد؛ مدل می‌تواند تصمیم بگیرد از ابزار یا تابعی استفاده کند، نتیجه را ببیند و چند مرحله برای رسیدن به هدف پیش برود.

مثال: کاربر می‌گوید «آخرین وضعیت سفارش من را بگو». Agent می‌تواند تشخیص دهد باید ابزار GetOrderStatus را صدا بزند، خروجی را بخواند و پاسخ قابل فهم تولید کند.

9) Prompt Engineering

طراحی ورودی به مدل برای مشخص‌کردن نقش، هدف، context، محدودیت‌ها و شکل خروجی است. Prompt خوب جای معماری درست، داده‌ی درست یا validation را نمی‌گیرد؛ فقط یکی از اجزای سیستم است.

10) این مفاهیم در یک سیستم واقعی چگونه کنار هم قرار می‌گیرند؟

نمونه: دستیار داخلی شرکت
Backend درخواست را می‌گیرد → اسناد مرتبط با Embedding و Vector Search پیدا می‌شوند → با RAG به prompt اضافه می‌شوند → LLM پاسخ می‌دهد → اگر نیاز به action باشد Agent یک Tool را صدا می‌زند → خروجی validate، log و monitor می‌شود.

فلش‌کارت‌های مرور

Training vs Inference؟
Training = یادگیری/تنظیم پارامترها؛ Inference = استفاده از مدل آموزش‌دیده روی ورودی جدید.
Embedding چه می‌کند؟
محتوا را به یک بردار عددی تبدیل می‌کند تا شباهت معنایی قابل محاسبه باشد.
RAG چه مسئله‌ای را حل می‌کند؟
دانش بیرونی/اختصاصی را قبل از Generation بازیابی کرده و به Context مدل اضافه می‌کند.
Agent چه چیزی فراتر از Chat دارد؟
می‌تواند Tool/Function فراخوانی کند و برای رسیدن به هدف، مراحل عملیاتی انجام دهد.
